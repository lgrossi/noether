# Export and reporting API contract

The current stable reporting contract is the CLI JSON emitted from the SQLite ledger plus the static
export dashboard HTML generated by CLI commands. `noet serve` now exposes matching reporting HTTP
surfaces, a live-dashboard data/update layer on top of the same ledger-backed reporting domain, and
artifact-backed simulation browsing for outputs generated by `noet simulate`.

## Implemented reporting endpoints

```text
GET /v1/reports/usage
GET /v1/reports/decisions
GET /v1/reports/traces/{trace_id}
GET /v1/reports/observations?kind=<prefix>&trace=<trace_id>
GET /v1/reports/dashboard?trace=<trace_id>
GET /v1/reports/dashboard-data?trace=<trace_id>
GET /v1/reports/updates
GET /v1/simulations
GET /v1/simulations/{simulation_id}
GET /v1/simulations/{simulation_id}/dashboard
GET /v1/simulations/{simulation_id}/strategies/{strategy_id}/usage
GET /v1/simulations/{simulation_id}/strategies/{strategy_id}/decisions
GET /v1/simulations/{simulation_id}/strategies/{strategy_id}/dashboard
GET /simulations
```

Additional reporting/live-dashboard notes:

- `GET /v1/reports/dashboard` returns export HTML as an artifact endpoint.
- `GET /v1/reports/dashboard-data` returns the JSON view model used by the served live dashboard.
- `GET /v1/reports/updates` emits SSE invalidation events so the live dashboard can re-fetch
  current report data without polling-only behavior.
- `GET /v1/simulations*` and `GET /simulations` are artifact-backed surfaces over the configured
  simulation output directory. They do not invent a separate server-owned simulation registry.

## Usage report shape

Mirror the current `report usage --json` output:

- `total_cost_usd`
- `rows[]` with project/provider/model/subject/token/cost/reservation fields
- optional `protected_adoption` summary with:
  - `unused_protected_opportunity_usd`
  - `carryover_liability_usd`
  - `low_adopters[]`
  - `high_adopters[]`

This is the export surface for budget usage, unused budget opportunity, adoption coverage inputs,
and carryover liability.

## Decisions report shape

Mirror the current `report decisions --json` output:

- `occurred_at`
- `kind` (`decision.allow`, `decision.warn`, `decision.deny`)
- `summary`
- optional `routing`:
  - `selected_budget_id`
  - `matched_entity`
  - `selection_reason`
  - `rejected_budget_id`
  - `rejected_budget_reason`
  - `model_check`
  - `budget_window_remaining_usd`
  - optional `budget_window_mode`
  - optional `budget_window_started_at`
  - optional `budget_window_ends_at`
- optional `limit_hits[]`:
  - `rule_id`
  - `reason`
  - `severity`
  - optional `window_id`
  - optional `window_mode`
  - optional `window_started_at`
  - optional `window_ends_at`
  - optional `projected_spend_usd`
  - optional `max_usd`
  - optional `scope_entity`

This is the export surface for denials, fallbacks, remaining budget room, and limit-hit reporting.

When an explicit tumbling budget is selected, `routing` carries the active bucket bounds. When a
spend-window limit fires, `limit_hits[]` carries the evaluated window id/mode, bounds, projected
spend, max spend, and matched scope entity so JSON exports and review surfaces do not need to
reverse-engineer those details from prose.

## Trace and observation shapes

Mirror the current CLI output shapes exactly:

- `report trace --json` returns an object with:
  - `trace_id`
  - chronological `items[]`
  - each item has `kind`, `summary`, and optional routing/limit fields on decision items
- `report observations --json` returns a bare array of `TraceReportItem` values ordered
  newest-first

Trace exports are the review surface for one run's decision, usage, tool, lifecycle, and
observation story. Observation exports remain a filtered event stream rather than a wrapped trace
document.

## Simulation artifact surface

Simulation browsing is intentionally file-backed rather than ledger-backed.

- `GET /v1/simulations` returns a JSON array of available simulation artifact summaries, including
  comparison and per-strategy surface URLs.
- `GET /v1/simulations/{simulation_id}` returns the generated `simulation-report.json` content for
  one simulation directory.
- `GET /v1/simulations/{simulation_id}/dashboard` returns the top-level simulation comparison HTML
  artifact.
- `GET /v1/simulations/{simulation_id}/strategies/{strategy_id}/usage` and `/decisions` return the
  generated per-strategy report JSON artifacts.
- `GET /v1/simulations/{simulation_id}/strategies/{strategy_id}/dashboard` returns the generated
  per-strategy static export dashboard HTML artifact.
- `GET /simulations` provides a browser-readable index over the same artifact set.

These routes are available after `noet simulate <file>` writes outputs into the configured
simulation directory, which defaults to `.noet/simulations`.

## API design constraints

- preserve the current JSON field names to avoid drift between CLI and HTTP exports;
- keep filtering simple: kind prefix and trace id are enough for the first export API;
- return static export dashboard HTML as a rendered artifact, not as a new source of truth;
- expose simulation review over generated artifacts rather than pretending simulations are live
  server-owned records;
- do not require a shared-storage migration before defining the read contract;
- keep local SQLite and future shared storage behind the same report/export shapes.
